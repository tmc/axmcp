2026-05-19 gputrace/Xcode parity pass

- `axmcp screenshot --help` tries the direct screenshot path with app name
  `--help` before printing help. It eventually prints usage, but the preamble
  is noisy and looks like a failed screenshot command.
- Xcode performance windows can report an empty or "untitled" window title in
  `ax_snapshot` even when `ax_list_windows` previously showed the trace title.
  This makes saved evidence harder to tie back to the target trace.
- AX snapshots were useful for static evidence, but selecting Xcode performance
  tabs and rows was more reliable through Computer Use element indexes. The
  AX tree exposes many duplicate unlabeled buttons for the tab strip and
  toolbar, so it is hard to target "Timeline", "Shaders", or "Counters" from
  AXMCP alone without coordinates.
- Brave local-file verification for generated `current.html` exposed the page
  mostly as nested generic `AXGroup` nodes. OCR could see text such as "GPU
  Timeline Viewer", "Occupancy", and "Instruction Throughput", but the AX tree
  did not expose useful page controls or text nodes, and the OCR payload was
  very large and truncated. This makes AX-only assertions against local HTML
  brittle unless the page adds accessible names or the tool can expose DOM text.

2026-05-20 gputrace MLX metal_debug trace

- A Metal debug MLX trace can contain readable embedded source sidecars, but
  `gputrace shader-source` does not index those in-bundle source files. For
  example, `source_debug_qwen2_modelir_tokens_8_to_9...gputrace` contains
  text sidecars with `#line 1 "mlx/backend/metal/kernels/bf16.h"` and
  `using namespace metal`, while `gputrace shader-source ... affine_qmv...`
  still reports `source file for shader ... not found`. This leaves source
  connected in the capture bundle, but not yet connected through the CLI or
  pprof source-line view.
