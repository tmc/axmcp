# axcdp completion audit

This audit maps the requested CDP behavior to the artifacts that implement or
explicitly refuse it. `axcdp` has a bounded AX-backed contract below; it is not
a full browser backend. When `-browser-cdp` is configured, browser-only target
traffic is proxied to a real browser DevTools endpoint rather than synthesized
from AX data.

## Contract

`axcdp` must expose macOS Accessibility through Chrome DevTools Protocol
endpoints without fabricating browser data. A method is supported only when it
is backed by macOS Accessibility, screen capture, native overlay/input, or a
harmless DevTools setup control.

The DOM surface is simulated only as a CDP protocol shape over real AX
elements. Live preview and highlighting are not simulated: screenshots and
screencast frames use real screen pixels, and highlights draw native overlays
on real macOS coordinates.

## Checklist

| Requirement | Evidence |
| --- | --- |
| Default remote debugging port is first in Chrome/Brave discovery. | `cmd/axcdp/main.go` defaults TTY server mode to `:9221`. |
| The live AX server has a stable TCC identity. | `startMacApp` configures macgo as `axcdp` with bundle id `dev.tmc.axcdp`, Accessibility and Screen Recording permissions, signing selected by `internal/macsigning`, UI/permission identity assignment, and explicit TCC requests before serving. Live serving should use a built binary, not transient `go run` paths. |
| `/json/version` is accepted by Chrome DevTools without a remote-newer warning. | `cmd/axcdp/cdp_server.go` returns protocol `1.3` and stable Chrome 120 metadata. |
| `/json/list` exposes inspectable AX targets. | `handleList` returns one root page target, one root Node-compatible target, and one page target per visible macOS window. It does not advertise app-level page rows in the general inspect list because an app is not a single screencast viewport. |
| macOS apps are not duplicated as fake Node targets. | `handleList` only adds the root Node-compatible target; `verifyCDPEndpoint` rejects app URLs with type `node`. |
| Chrome DevTools dedicated Node frontend has a target to attach to. | `nodeTarget` advertises a root `type: node` target with Node favicon and WebSocket URL. |
| Selecting an element in DevTools can highlight the real macOS view. | `DOM.setInspectedNode`, `Overlay.highlightNode`, `Overlay.highlightRect`, and `Overlay.highlightQuad` use AX node bounds and native overlay. |
| Live preview uses real pixels. | `Page.captureScreenshot` and `Page.startScreencast` call the screenshot path backed by `CGWindowListCreateImage`; the live verifier checks screenshot data and a `Page.screencastFrame`. |
| The advertised protocol has a source of truth. | `/json/protocol` is generated by `cdpProtocolDomains`; `/json/coverage` is generated by `cdpCoverageEntries`. |
| Protocol and coverage cannot drift silently. | `TestCDPCoverageMatchesAdvertisedProtocol` and `verifyCoverageMatchesProtocol` require every advertised method to have a coverage entry. |
| Unsupported browser-only CDP is refused, not faked. | `cdpUnsupportedMethods` lists major browser-only methods; tests and the live verifier require `-32601` method-not-found. |
| Browser target creation and close are not faked. | On AX-only servers, `/json/new` and `/json/close/<id>` return `501 Not Implemented`; with `-browser-cdp`, they proxy to a real browser endpoint. Tests and live verifiers check both paths. |
| The AX pass-through domain works through CDP WebSocket. | `dispatchCDP` routes `AX.*` to the local AX dispatcher; the live verifier checks `AX.getVersion`. |
| Browser-only CDP has a real backend when enabled. | `-browser-cdp` imports real browser targets, proxies target WebSockets, and proxies browser-backed `Target.createTarget`/`Target.closeTarget`. |
| Browser proxy coverage is verified end to end. | `-verify-browser-cdp` checks browser-backed target creation, direct target WebSocket proxying, `Runtime.evaluate`, `Network.enable`, `Page.navigate`, and target close. |
| The sibling `../cdp` CLI can attach and send raw CDP commands. | Live checks use `GOWORK=off go run ./cmd/cdp -remote-host 127.0.0.1 -remote-port 9221 ...`. |

## Unsupported boundary

The following categories are intentionally outside the AX-backed contract. They
are available only on browser targets when `-browser-cdp` is configured with a
real browser endpoint:

- Arbitrary browser navigation and reload. `Page.navigate` is limited to
  axcdp preview URLs that retarget the AX app/window view.
- Browser target creation or close.
- JavaScript VM execution beyond primitive AX metadata expressions.
- Network response bodies.
- Storage, IndexedDB, CacheStorage, and database inspection.
- Chrome's internal page DOM, CSS cascade, layout engine, and script worlds.

The explicit unsupported method list is:

- `Browser.close`
- `Browser.setWindowBounds`
- `Target.createTarget`
- `Target.closeTarget`
- `Page.reload`
- `Page.createIsolatedWorld`
- `Runtime.awaitPromise`
- `Runtime.callFunctionOn`
- `Runtime.runScript`
- `Runtime.queryObjects`
- `Network.getResponseBody`
- `Storage.getStorageKeyForFrame`
- `IndexedDB.requestDatabaseNames`
- `CacheStorage.requestCacheNames`
- `Overlay.setInspectMode`
- `Input.insertText`

Returning synthetic data for those categories from AX-only targets would make
the implementation look more complete while being less correct. AX-only targets
should continue to return JSON-RPC method-not-found (`-32601`) or HTTP `501`,
as appropriate.

## Gates

Run these before treating the AX-backed CDP contract as healthy. The live
verifiers require an already-running `axcdp` endpoint with Accessibility and
Screen Recording permission granted:

```sh
go test ./cmd/axcdp
go run ./cmd/axcdp -verify-cdp http://127.0.0.1:9221
go run ./cmd/axcdp -verify-target http://127.0.0.1:9221 -target <target-title-or-id>
```

`-verify-target` requires `-target`; the selector may match a target title, id,
or URL substring.

Run the browser verifier only against a combined server started with
`-browser-cdp`:

```sh
go run ./cmd/axcdp -verify-browser-cdp http://127.0.0.1:<combined-port>
```

`go test ./...` is a broader repository gate, not a substitute for the live
CDP/TCC checks above.

Optional sibling CLI checks:

```sh
cd ../cdp
GOWORK=off go run ./cmd/cdp -remote-host 127.0.0.1 -remote-port 9221 -list-tabs
GOWORK=off go run ./cmd/cdp -remote-host 127.0.0.1 -remote-port 9221 -tab <target-id> -command 'Schema.getDomains' -format json -timeout 5
GOWORK=off go run ./cmd/cdp -remote-host 127.0.0.1 -remote-port 9221 -tab <target-id> -command 'AX.getVersion' -format json -timeout 5
GOWORK=off go run ./cmd/cdp -remote-host 127.0.0.1 -remote-port 9221 -tab <target-id> -command 'Page.navigate {"url":"https://example.com"}' -format json -timeout 5
```
